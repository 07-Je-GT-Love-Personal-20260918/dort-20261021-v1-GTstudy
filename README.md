## v1.1 使用说明

- 新增 `atlas.html`：六城文化、史实与解释分栏、因果图、关键日期及记忆钩；史料逐项提供来源。
- 地图成对呈现：原创可点选思想网络示意图始终可用；现代在线地图按需加载，支持 Esri 卫星、Esri 地形及 OpenTopoMap，失败自动尝试备用来源。在线服务的全球可达性受当地网络影响，不能保证处处可用；影像并非实时拍摄，现代地图也不代表1618年疆界。
- 右下角“⋯”展开返回、前进、主页、图谱、标记与笔记；常驻小按钮可到顶部或底部。
- 选中文字后使用八种标记：核心金底、应用绿底、经文蓝字、难点玫红、实线、虚线、加粗、区块。触屏可开启段落标记模式，点按正文后选择样式。
- 笔记支持旁注、搜索、跨页定位、JSON备份和导入、Markdown导出；原有自由笔记保留。笔记只存本浏览器、当前域名，三个站点不会自动同步；换设备或清理数据前请备份。
- 地图脚本与底图延迟加载；滚动进度使用逐帧合并更新；屏外装饰动画与路线轮播暂停；尊重系统减少动态效果设置。Leaflet本地托管，无运行时脚本CDN依赖。

## 文本与准确性

- 三份普世信经净读版采用CCI网站已读取的正文，三项联合信条以用户提供《中国改革宗教会敬拜手册》（2015）为底本。没有上传整部PDF。
- 原文保留字词和标点，展示时清理物理换行。`reference-text.json` 保留对应页的提取结果，便于追踪。
- **三份普世信经已按CCI网站正文录入并作字符核对；三项联合信条尚未完成与网站全文比对，不能标称六份全文均为网站逐字校定版。** 已读取该站信经页面、信条介绍、圣餐仪文及部分证道，未声称遍历全站。
- 附件未收录完整大会结语，主页面提供明确标注的原创提要及外部全文入口，不能当作CCI原文。
- 文章解释与附件译文分别标示。补充英文资料来自 CanRC、URCNA；历史资料来自荷兰国家档案馆、国家图书馆及多特博物馆。
- 中文译本版权属于原出版委员会。此学习重排不主张原译文版权；网站没有任何组织正式审定背书。

## 文件

- `dist/`：可直接上传静态托管的八个 HTML 页面、样式与交互文件。
- `enhancements.py`：地图、历史文化页与阅读工具的构建扩展。
- `history-culture.json`：历史文化事实、解释、来源及时间线。
- `dist/study.js`、`dist/study.css`：共用导航、八色标记、笔记与阅读优化；`dist/maps.js`：地图联动和底图容错。
- `dist/vendor/leaflet/`：本地地图引擎1.9.4与许可证；底图版权标示在地图中。
- `build.py`：从文本底本与原创解读重建网页。
- `reference-text.json`：六份信经信条所在页的文本底本，不含后续仪文、教规等全书内容。
- `cci-creeds.json`：三份普世信经的CCI正文记录；`TEXT-COLLATION.json`：其与PDF的字符差异及阅读页校验摘要。
- `commentary.json`：59条教义及34项驳谬的原创解读、经文与应用。
- `parsed-dort.json`：按篇章与条号整理的多特文本。
- `.github/workflows/pages.yml`：main分支更新后自动发布已生成的 `dist/`。
- `vercel.json`：Vercel静态发布配置。

## 持续修改

需要 Python 3 与标准库。无运行时框架、外部字体、CDN脚本或追踪代码。

```sh
python build.py
python -m http.server 8765 --directory dist
```

若需重新从原PDF提取，需要 PyMuPDF；日常修改直接使用已保存的文本底本即可。浏览器语音依赖设备所安装语音，可停止播放；笔记仅存于浏览器本机，不会上传。

修改解读编辑 `commentary.json`，修改编排编辑 `build.py`，修改视觉与交互编辑 `dist/style.css`、`dist/app.js`、`dist/reader.js`。生成器不会覆盖这三个前端文件。每次修改后重建、检查，再提交到 main。

## 部署和恢复

GitHub Pages由工作流发布 `dist/`，仓库 Pages 源应设为 GitHub Actions。Vercel可运行 `vercel deploy --prod --yes`，Vercel Git连接尝试未成功，当前通过CLI发布，不宣称其已建立Git自动部署。Surge可运行 `surge dist dort-20261021-v1-gtstudy.surge.sh`。凭据应通过各平台既有登录或受保护的环境配置管理，禁止写入源文件。

初始稳定版本以标签 `v1.0.0-20261021` 保留；本次增强版使用 `v1.1.0-20261024`。恢复时先创建新分支以保留后续修改：

```sh
git switch -c restore-v1 v1.0.0-20261021
```

如要恢复线上版本，将审核后的旧版内容作为新的恢复提交合入 main，再重新部署三个平台，不强推删除历史。
